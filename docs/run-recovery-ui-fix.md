# 运行恢复按钮与错误提示修复

## 问题

中断的旧运行恢复成功后，旧记录仍显示“恢复运行”。后端拒绝重复执行同一检查点，但前端把操作错误保存在整个运行页，切换记录仍显示该错误。从对话进入时，初始运行ID还可能反复覆盖用户后续选择。

## 修复

- 列表、详情和Trace返回持久后续运行ID与状态；旧记录显示“查看后续运行”，只读取并跳转。
- 另一窗口已经恢复时，后端返回 `already_recovered` 原因和子运行ID，前端读取已有执行，不再次恢复。
- 后续运行不在最新200条列表时仍可按ID读取；已删除时显示禁用状态，旧检查点仍不可重复执行。
- 中断、恢复、打开后续的错误归属于当前详情实例；切换记录清除，迟到失败不串记录，迟到成功不抢走其他记录的焦点。
- 初始运行ID仅在首次进入或外部目标变化时生效。
- 保留恢复唯一认领、事务、工作区和审批保护；恢复入口与后端支持状态一致。

## 验证

修复前组件在相同浏览器检查中复现错误残留：预期0个提示、实际1个。修复后10项浏览器交互检查通过，覆盖中断恢复链、错误隔离、迟到响应、初始跳转、已有/列表外/已删除后续，以及另一窗口先恢复的竞争情况。

后端64项隔离回归通过，其中新增3项检查后续链接、删除后续和列表过滤；相关18项生命周期检查已在日常同步后复验。浏览器验证挂载真实React组件，使用可控RPC，不代替真实模型或外部服务验证。旧四套综合验收成绩未因本次定向回归重新计分。

代码位于 `backend/kore_next/application.py`、`backend/kore_next/run_lifecycle.py`、`desktop/src/RunExplorer.tsx` 和 `desktop/src/types.ts`；测试命令见[贡献指南](../CONTRIBUTING.md)。
