# KoreAgent Next 连接器说明

连接器把远端邮箱和飞书数据同步到本地 SQLite，再由桌面端展示和处理。读取同步和远端写入是两条不同路径：同步不会自动修改远端对象；发邮件、创建或修改日历、写入飞书任务和云文档必须经过外部操作预览与审批。

## 1. 支持的连接器

| 连接器 | 远端服务 | 主要能力 | 授权方式 |
| --- | --- | --- | --- |
| 邮件 | QQ、163、126、139 或自定义 IMAP/SMTP | 收信、发信、正文、附件、已读和本地完成状态 | IMAP/SMTP 应用专用授权码 |
| 日历 | 飞书主日历 | 同步、创建、修改和删除日历事件 | 飞书 OAuth |
| 任务 | 飞书任务 | 同步、创建、修改、完成和删除任务 | 飞书 OAuth |
| 文档 | 飞书云文档 | 同步文档、创建、追加、更新文本块和删除文档 | 飞书 OAuth |

一次飞书 OAuth 会建立 `calendar`、`todo` 和 `notes` 三个本地连接，但健康状态和同步游标分别记录。

## 2. 邮箱连接器

### 2.1 配置和首次同步

在邮箱服务商后台开启 IMAP/SMTP，并生成应用专用授权码。进入“信息中心 → 收件箱 → 配置 QQ/163”，选择服务商，填写邮箱地址和授权码，再选择首次同步范围：最近 7 天、30 天（默认）、90 天、1 年或不限时间。默认范围不会删除远端历史邮件；需要旧邮件时点击“加载更早邮件”，系统沿 UID 游标向前分页。

内置服务器为：

| 服务商 | IMAP | SMTP |
| --- | --- | --- |
| QQ | `imap.qq.com:993` | `smtp.qq.com:465` |
| 163 | `imap.163.com:993` | `smtp.163.com:465` |
| 126 | `imap.126.com:993` | `smtp.126.com:465` |
| 139 | `imap.139.com:993` | `smtp.139.com:465` |

授权码由本地 SecretStore 保存；Windows 使用 DPAPI。不要把授权码写进数据库、日志或 Git 仓库。

### 2.2 同步和收件箱

同步保存主题、发件人、收件人、纯文本正文、日期、Message-ID、附件元数据和本地状态。HTML 正文会转成安全文本，不在桌面端执行邮件脚本。同步使用 IMAP UID、去重键和游标，重复同步不会重复导入。

收件箱状态是本地状态：未读/已读表示是否在本地查看，未完成/已完成表示是否处理过。它们不会删除、移动或改变远程邮件；邮件必须先已读才能本地完成。工作台外部信息是同一批本地项目经过重要性和建议行动筛选后的派生视图，不保证与收件箱逐条相同。

### 2.3 附件和发送

附件列表只返回文件名、MIME 类型和大小。下载时 Host 检查归属并发放短期、一次性的下载令牌。`email_send` 支持收件人、抄送、密送、主题、纯文本或 HTML、附件以及回复/转发引用。发送前展示预览，审批后才调用 SMTP。

SMTP 接受只表示服务器接收，不表示收件人已阅读。网络超时或连接中断会标记为 `uncertain`，应先在“执行中心 → 外部操作”核实远端结果，再决定是否继续。

### 2.4 IDLE 和轮询

Host 会尝试 IMAP IDLE。服务商不支持、网络不稳定或监听失败时自动回退轮询，并在连接器健康页显示实际状态。QQ/163 是否支持 IDLE 取决于账号和服务端，不能保证邮件到达后立即显示；也可以手动同步。

## 3. 飞书连接器

### 3.1 应用和 OAuth

在 `backend/.env` 中配置：

```dotenv
KORENEXT_FEISHU_APP_ID=cli_xxxxxxxxx
KORENEXT_FEISHU_APP_SECRET=your_app_secret
KORENEXT_FEISHU_REDIRECT_URI=http://127.0.0.1:8765/oauth/feishu/callback
```

开放平台中的回调地址必须逐字符一致。修改权限或 Scope 后，需要发布新的应用版本并重新授权。默认 Scope 由代码提供，也可以用 `KORENEXT_FEISHU_SCOPES` 覆盖；长期运行需要 `offline_access`，云文档删除需要 Drive 写权限。

可选配置：

```dotenv
KORENEXT_FEISHU_SCOPES=
KORENEXT_FEISHU_VERIFICATION_TOKEN=
KORENEXT_FEISHU_ENCRYPT_KEY=
```

在收件箱点击“飞书 OAuth”。授权成功后，Host 会分别建立日历、任务和文档连接并执行同步。

### 3.2 日历

同步标题、描述、开始/结束时间、地点、远端事件 ID 和状态。支持 `feishu_calendar_event_create`、`feishu_calendar_event_update` 和 `feishu_calendar_event_delete`。创建、修改和删除都需审批。当前以用户主日历为目标，不提供完整的参与人、重复事件或多日历编辑器。

### 3.3 飞书任务

同步标题、描述、截止时间、优先级、状态和远端 ID。支持创建、修改标题/描述/截止时间/`todo` 或 `done` 状态，以及删除任务。Host 维护展示 ID 与飞书 API 所需 UUID/GUID 的映射。写入成功不保证立刻出现在下一次列表同步中，可手动同步。

### 3.4 云文档

同步标题、摘要、更新时间、远端文档 ID 和同步状态。支持：

- `feishu_document_create`：创建文档，可在创建后追加正文；
- `feishu_document_append`：追加文本块；
- `feishu_document_block_update`：更新已知文本块；
- `feishu_document_delete`：调用 Drive 删除接口，将文档移入回收站。

创建成功但追加失败时会保留文档 ID，允许继续执行或人工处理。当前不覆盖表格、复杂富文本、分享设置和完整块编辑器。

### 3.5 Token 刷新和重新授权

Access Token 和 Refresh Token 保存在本地 SecretStore，不写入 SQLite、运行记录或审计正文。同步和写入前会检查过期时间，接近过期时尝试刷新；刷新失败、Scope 不足或 Token 丢失时，连接器状态变为 `reauthorize_required`，健康页提供重新授权入口。

实际有效期由飞书返回的 `expires_in` 和平台策略决定，不能按固定一两个小时保证。重新授权后，日历、任务和文档三项本地连接一起更新授权元数据。

## 4. 同步、工作台和错误中心

同步结果保存最后成功时间、同步游标、导入数量、重试次数、下一次重试时间和错误。连接器健康页、设置页和 Host `/health` 使用同一份本地状态。

错误中心分为当前错误和历史错误：当前错误需要确认、标记恢复或重试，已恢复错误进入历史；清理只删除本地错误记录，不会删除远端邮件、事件、任务或文档。

工作台的外部信息是连接器项目的派生视图。邮件、未来日历事件、未完成任务和包含明确负责人/截止事项的文档更容易进入待处理列表；普通订阅、营销邮件、垃圾邮件和没有行动建议的内容通常只保留在收件箱。

## 5. 外部动作和恢复

外部动作通常经历：

```text
预览 → 待审批 → 已批准 → 执行中 → 成功 / 部分成功 / 失败 / 结果未知
```

多个动作组成的 `connector_workflow` 是本地顺序 Saga，不是分布式事务：全部成功时完成；前面成功、后续失败时部分成功；超时且无法判断远端状态时结果未知。结果未知时先查询远端，不要直接重复发送；已知远端对象 ID 时可以继续失败步骤、重试或请求补偿删除。预览、审批、远端结果和恢复动作都会进入审计，敏感凭据会脱敏。

## 6. Webhook、断开和清理

Host 提供飞书回调地址：

```text
POST http://127.0.0.1:8765/webhooks/feishu
```

本地地址无法直接被飞书公网访问。启用 Webhook 需要自行提供公网反向代理、TLS、域名和开放平台事件配置；项目不会自动暴露本地 Host。没有公网回调时继续使用轮询。

“断开连接”清理指定连接器的本地账号状态和同步缓存，不删除远端对象；“撤销全部授权”清理邮箱授权码、飞书 Token 和连接器缓存；`app.initialize` 和 `data.delete_all` 是高影响的本地清理操作，执行前应备份数据库。云文档删除按飞书 API 行为进入回收站。

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| 邮箱无法连接 | 确认开启 IMAP/SMTP，使用应用专用授权码，检查端口和网络 |
| 新邮件没有立即出现 | 查看 IDLE 状态；不支持时手动同步或等待轮询 |
| 飞书权限不足 | 补齐对应 Scope、发布应用新版本并重新 OAuth |
| Token 很快过期 | 确认 `offline_access` 已授予；刷新失败时在健康页重新授权 |
| 外部动作结果未知 | 先核实远端，再继续、重试或补偿，避免重复发送 |
| 工作台和收件箱数量不同 | 工作台是经过重要性和行动建议过滤后的派生视图，收件箱是同步项目列表 |
